全文导读

这篇不长，但容易把 ReAct 读成「又一种思维链」。下面先给出主张、机制、证据与精读路径。读完这一页，再带着一个具体问题进入正文。

一句话主张。 让语言模型把思考 / 行动 / 观察交错写进同一条轨迹：思考用来拆目标、改计划、处理例外；行动用来查 Wikipedia、逛网页或在环境里动手。只想会幻觉，只做会空转，两者协同才站得住。

和 AI 工程、智能体、Cordiverse 的关系

ReAct 是后来几乎所有 agent harness 的协议原型：一步思考、一步工具调用、一步环境观察，循环下去。Cordiverse 讨论的运行框架要组合工具套件、治理权限、编排子智能体——这些循环在实现里，多半仍是思考 / 行动 / 观察。它对 AI 工程的直接用处可以收成一句：把「推理」从草稿纸挪进可检查的行动轨迹，幻觉能被外部观察打断。

它没有处理工具如何卸载、依赖如何声明、一次坏的自修改如何隔离。那是 Cordiverse 要补的时空可组合性。展开判断见独立的读后评论，此处不占导读。

问题从哪来

思维链揭示了 LLM 会「自言自语」解题，但闭卷编造事实；WebGPT、SayCan、Inner Monologue 让模型行动，却不把灵活的内部思考写成一等行动。人类做饭时两者本来就是交织的：边想「没盐就用酱油」，边开冰箱核对。

缺的不是又一条更长的思维链，而是把语言空间并进行动空间：思考不改环境、没有观察，只改上下文，好让下一步动得更准。

摘要

尽管大语言模型（LLM）已在语言理解与交互式决策等任务上展现出色表现，其推理能力（例如思维链提示）与行动能力（例如生成行动计划）此前主要被当作两个分开的课题来研究。本文探索让 LLM 以交错方式同时生成推理轨迹与任务相关行动，从而使二者产生更强的协同：推理轨迹帮助模型诱导、跟踪并更新行动计划，同时处理例外；行动则使模型能够与外部来源（如知识库或环境）对接并收集额外信息。我们将该方法命名为 ReAct，并将其应用于多样的语言与决策任务，证明其相对最先进基线更有效，同时提升了人类可解释性与可信度。具体而言，在问答（HotpotQA）与事实验证（Fever）上，ReAct 通过与一个简单的 Wikipedia API 交互，克服了思维链推理中常见的幻觉与误差传播问题，并生成比没有推理轨迹的基线更可解释、更接近人类的解题轨迹。此外，在两个交互式决策基准（ALFWorld 与 WebShop）上，ReAct 仅用一或两条上下文示例提示，就分别以 34% 与 10% 的绝对成功率超过模仿学习与强化学习方法。

引言

人类智能的一个独特特征，是能够把面向任务的行动与言语推理（或内心言语，Alderson-Day & Fernyhough, 2015）无缝结合。这一能力被认为在人类认知中扮演重要角色：它支持自我调节或策略化（Vygotsky, 1987; Luria, 1965; Fernyhough, 2010），并维持工作记忆（Baddeley, 1992）。以在厨房做一道菜为例。在任意两个具体行动之间，我们可能用语言推理来跟踪进度（「既然都切好了，我该把锅里的水烧热」），处理例外或按情境调整计划（「没有盐，那就用酱油和胡椒代替」），并意识到何时需要外部信息（「面团怎么和？我上网查一下」）。我们也可能行动（打开食谱看书、打开冰箱、检查食材）来支撑推理并回答问题（「我现在能做什么菜？」）。这种「行动」与「推理」之间的紧密协同，使人类能快速学习新任务，并在未见过的情境或信息不完备时仍能做出稳健的决策或推理。

In this work, we present ReAct, a general paradigm to combine reasoning and acting with language models for solving diverse language reasoning and decision making tasks (Figure 1). At time step t, an agent receives an observation ot ∈O from the environment and takes an action at ∈A following some policy π(at|ct), where ct = (o1, a1, · · · , ot−1, at−1, ot) is the context to the agent. Learning a policy is challenging when the mapping ct 7→at is highly implicit and requires extensive computation. For example, the agent shown in Figure 1(1c) is unable to generate the correct ﬁnal action (Act 4) to ﬁnish the QA task as it requires complex reasoning over the trajectory context (Question, Act 1-3, Obs 1-3). Similarly, the agent shown in Figure 1(2a) fails to comprehend from the context that sinkbasin 1 does not contain peppershaker 1, thus keep producing hallucinating actions. The idea of ReAct is simple: we augment the agent’s action space to ˆ A = A ∪L, where L is the space of language. An action ˆat ∈L in the language space, which we will refer to as a thought or a reasoning trace, does not affect the external environment, thus leading to no observation feedback. Instead, a thought ˆat aims to compose useful information by reasoning over the current context ct, and update the context ct+1 = (ct, ˆat) to support future reasoning or acting. As shown in Figure 1, there could be various types of useful thoughts, e.g. decomposing task goals and create action plans (2b, Act 1; 1d, Thought 1), injecting commonsense knowledge relevant to task solving (2b, Act 1), extracting important parts from observations (1d, Thought2, 4), track progress and transit action plans (2b, Act 8), handle exceptions and adjust action plans (1d, Thought 3), and so on. However, as the language space L is unlimited, learning in this augmented action space is difﬁcult and requires strong language priors. In this paper, we mainly focus on the setup where a frozen large language model, PaLM-540B (Chowdhery et al., 2022)1, is prompted with few-shot in-context examples to generate both domain-speciﬁc actions and free-form language thoughts for task solving (Figure 1 (1d), (2b)). Each in-context example is a human trajectory of actions, thoughts, and environment observations to solve a task instance (see Appendix C). 领域

我们考虑两个对知识检索与推理具有挑战的数据集：（1）HotPotQA（Yang et al., 2018），一个需要在两段或更多 Wikipedia 段落上推理的多跳问答基准；（2）FEVER（Thorne et al., 2018），一个事实验证基准，每条声明被标注为 SUPPORTS、REFUTES 或 NOT ENOUGH INFO，取决于是否存在可验证该声明的 Wikipedia 段落。本文对两项任务都采用仅问题设定：模型只收到问题/声明作为输入，没有支持段落，必须依赖内部知识，或通过与外部环境交互来检索知识以支撑推理。

行动空间

我们设计了一个简单的 Wikipedia Web API，用三类行动支持交互式信息检索：（1）search[entity]，若对应实体维基页存在则返回其前 5 句，否则给出 Wikipedia 搜索引擎的前 5 个相似实体；（2）lookup[string]，返回页面中包含该字符串的下一句，模拟浏览器上的 Ctrl+F；（3）finish[answer]，以 answer 结束当前任务。我们注意到，该行动空间大多只能按精确篇名检索段落的一小部分，显著弱于最先进的词法或神经检索器。目的是模拟人类如何与 Wikipedia 交互，并迫使模型通过显式的语言推理来检索。

Baselines We systematically ablate ReAct trajectories to build prompts for multiple baselines (with formats as Figure 1(1a-1c)): (a) Standard prompting (Standard), which removes all thoughts, actions, observations in ReAct trajectories. 基线

我们系统消融 ReAct 轨迹，为多种基线构建提示（格式如图 1(1a–1c)）：（a）标准提示（Standard），去掉 ReAct 轨迹中的全部思考、行动、观察。（b）思维链提示（CoT）（Wei et al., 2022），去掉行动与观察，作为仅推理基线。我们还构建自洽基线（CoT-SC）（Wang et al., 2022a;b）：推理时以解码温度 0.7 采样 21 条 CoT 轨迹并取多数答案，发现其持续优于 CoT。（c）仅行动提示（Act），去掉 ReAct 轨迹中的思考，松散类似于 WebGPT（Nakano et al., 2021）与互联网交互来答题——尽管任务与行动空间不同，且 WebGPT 用模仿与强化学习而非提示。

结合内部与外部知识

如第 3.3 节将详述，我们观察到 ReAct 展示的解题过程更符合事实、更落地，而 CoT 在组织推理结构上更准确，但容易受幻觉事实或思考之害。因此我们提出把 ReAct 与 CoT-SC 结合，并按如下启发式让模型决定何时切换：A）ReAct → CoT-SC：当 ReAct 在给定步数内未能返回答案时，回退到 CoT-SC。HotpotQA 与 FEVER 分别设 7 步与 5 步，因为我们发现更多步数并不能提升 ReAct 性能3。B）CoT-SC → ReAct：当 n 条 CoT-SC 样本中的多数答案出现次数少于 n/2（即内部知识可能不足以自信支撑该任务）时，回退到 ReAct。

微调

由于大规模手工标注推理轨迹与行动很困难，我们采用类似 Zelikman et al.（2022）的自举方法：用 ReAct（以及其他基线）生成的 3,000 条答案正确的轨迹，微调较小语言模型（PaLM-8/62B），使其在给定输入问题/声明的条件下解码整条轨迹（全部思考、行动、观察）。更多细节见附录 B.1。

ReAct 对 CoT

另一方面，ReAct 在 Fever 上优于 CoT（60.9 vs. 56.3），在 HotpotQA 上略落后（27.4 vs. 29.4）。Fever 上 SUPPORTS/REFUTES 的声明可能只差一点点（见附录 D.1），因此行动以检索准确、时新的知识至关重要。为更好理解 ReAct 与 CoT 在 HotpotQA 上的行为差异，我们分别从 ReAct 与 CoT 中随机抽取 50 条答案正确与 50 条答案错误（按 EM 判定）的轨迹（共 200 例），并在表 2 中手工标注成功与失败模式。若干关键观察如下：

A）幻觉对 CoT 是严重问题，使其成功模式中的假正例率远高于 ReAct（14% vs. 6%），并构成其主要失败模式（56%）。相比之下，得益于外部知识库，ReAct 的解题轨迹更落地、更由事实驱动、更可信。

By checking examples, we ﬁnd that ReAct is more likely to identify instruction-relevant products and options by reasoning to bridge the gap between noisy observations and actions (e.g. “For ‘space-saving ottoman bench for living room’, the item has options ‘39x18x18inch’ and ‘blue’ and seems good to buy.”). On the value of internal reasoning vs. external feedback To our knowledge, ReAct is the ﬁrst demonstration of combined reasoning and action using an LLM applied to an interactive environment within a closed-loop system. Perhaps the closest prior work is Inner Monologue (IM), from Huang et al. (2022b), in which actions from an embodied agent are motivated by an eponymous “inner monologue”. However, IM’s “inner monologue” is limited to observations of the environment state and what needs to be completed by the agent for the goal to be satisﬁed. In contrast, the reasoning traces in ReAct for decision making is ﬂexible and sparse, allowing diverse reasoning types (see Section 2) to be induced for different tasks. To demonstrate the differences between ReAct and IM, and to highlight the importance of internal reasoning vs. simple reactions to external feedback, we ran an ablation experiment using a thought pattern composed of IM-like dense external feedback. As can be seen in Table 3, ReAct substantially outperforms IM-style prompting (ReAct-IM) (71 vs. 53 overall success rate), with consistent advantages on ﬁve out of six tasks. Qualitatively, we observed that ReAct-IM often made mistakes in identifying when subgoals were ﬁnished, or what the next subgoal should be, due to a lack of highlevel goal decomposition. Additionally, many ReAct-IM trajectories struggled to determine where an item would likely be within the ALFWorld environment, due to a lack of commonsense reasoning. 关于内部推理与外部反馈的价值

据我们所知，ReAct 是首个在闭环系统中，把 LLM 的推理与行动结合起来并应用于交互环境的演示。或许最接近的先前工作是 Huang et al.（2022b）的 Inner Monologue（IM），其中具身智能体的行动由所谓「内心独白」驱动。然而，IM 的「内心独白」仅限于对环境状态的观察，以及智能体为满足目标还需完成什么。相比之下，ReAct 用于决策的推理轨迹灵活且稀疏，允许为不同任务诱导多样的推理类型（见第 2 节）。

Published as a conference paper at ICLR 2023 RELATED WORK Language model for reasoning Perhaps the most well-known work of using LLMs for reasoning is Chain-of-Thought (CoT) (Wei et al., 2022), which reveals the ability of LLMs to formulate their own “thinking procedure” for problem solving. Several follow-up works have since been performed, including least-to-most prompting for solving complicated tasks (Zhou et al., 2022), zero-shotCoT (Kojima et al., 2022), and reasoning with self-consistency (Wang et al., 2022a). Recently, (Madaan & Yazdanbakhsh, 2022) systematically studied the formulation and structure of CoT, and observed that the presence of symbols, patterns and texts is crucial to the effectiveness of CoT. Other work has also been extended to more sophisticated reasoning architecture beyond simple prompting. For example Selection-Inference (Creswell et al., 2022) divides the reasoning process into two steps of “selection” and “inference”. STaR (Zelikman et al., 2022) bootstraps the reasoning process by ﬁnetuning the model on correct rationales generated by the model itself. Faithful reasoning (Creswell & Shanahan, 2022) decomposes multi-step reasoning into three steps, each performed by a dedicated LM respectively. Similar approaches like Scratchpad (Nye et al., 2021), which ﬁnetunes a LM on intermediate computation steps, also demonstrate improvement on multi-step computation problems. In contrast to these methods, ReAct performs more than just isolated, ﬁxed reasoning, and integrates model actions and their corresponding observations into a coherent stream of inputs for the model to reason more accurately and tackle tasks beyond reasoning (e.g. interactive decision making). Language model for decision making The strong capability of LLMs has enabled them to perform tasks beyond language generation, and it is becoming more popular to take advantage of LLMs as a policy model for decision making, especially in interactive environments. WebGPT (Nakano et al., 2021) uses an LM to interact with web browsers, navigate through web pages, and infer answers to complicated questions from ELI5 (Fan et al., 2019). In comparison to ReAct, WebGPT does not explicitly model the thinking and reasoning procedure, instead rely on expensive human feedback for reinforcement learning. In conversation modeling, chatbots like BlenderBot (Shuster et al., 2022b) and Sparrow (Glaese et al., 2022) and task-oriented dialogue systems like SimpleTOD (Hosseini-Asl et al., 2020) also train LMs to make decision about API calls. Unlike ReAct, they do not explicitly consider the reasoning procedure either, and also relies on expensive datasets and human feedback collections for policy learning. In contrast, ReAct learns a policy in a much cheaper way, since the decision making process only requires language description of the reasoning procedure.6 LLMS have also been increasingly employed in interactive and embodied environments for planning and decision making. Perhaps most relevant to ReAct in this respect are SayCan (Ahn et al., 2022) and Inner Monologue (Huang et al., 2022b), which use LLMs for robotic action planning and decision making. In SayCan, LLMs were prompted to directly predict possible actions a robot can take, which is then reranked by an affordance model grounded on the visual environments for ﬁnal prediction. Inner Monologue made further improvements by adding the eponymous “inner monologue", which is implemented as injected feedback from the environment. To our knowledge, Inner Monologue is the ﬁrst work that demonstrates such a closed-loop system, which ReAct builds on. However, we argue that Inner Monologue does not truly comprise of inner thoughts — this is elaborated in Section 4. We also note that leveraging language as semantically-rich inputs in the process of interactive decision making has been shown to be successful under other settings (Abramson et al., 2020; Karamcheti et al., 2021; Huang et al., 2022a; Li et al., 2022). It is becoming more evident that with the help of LLMs, language as a fundamental cognitive mechanism will play a critical role in interaction and decision making. What is more, progress in LLMs has also inspired the development of versatile and generalist agents like Reed et al. (2022). CONCLUSION We have proposed ReAct – a simple yet effective method for synergizing reasoning and acting in large language models. Through a diverse set of experiments on multi-hop question-answering, fact checking, and interactive decision-making tasks, we show that ReAct leads to superior performance with interpretable decision traces. Despite the simplicity of our method, complex tasks with large action spaces require more demonstrations to learn well, which unfortunately can easily go beyond the input length limit of in-context learning. 相关工作

用于推理的语言模型

或许最著名的用 LLM 做推理的工作是思维链（CoT）（Wei et al., 2022），它揭示了 LLM 能为解题形成自己的「思考程序」。随后有若干跟进工作，包括用 least-to-most 提示解决复杂任务（Zhou et al., 2022）、零样本 CoT（Kojima et al., 2022），以及带自洽的推理（Wang et al., 2022a）。最近，（Madaan & Yazdanbakhsh, 2022）系统研究了 CoT 的表述与结构，观察到符号、模式与文本的存在对 CoT 有效性至关重要。其他工作也已扩展到比简单提示更复杂的推理架构。例如 Selection-Inference（Creswell et al., 2022）把推理过程分成「选择」与「推断」两步。STaR（Zelikman et al., 2022）通过对模型自己生成的正确理由做微调来自举推理过程。忠实推理（Creswell & Shanahan, 2022）把多步推理分解为三步，每步由专用 LM 分别执行。类似方法如 Scratchpad（Nye et al., 2021）在中间计算步骤上微调 LM，也在多步计算问题上展示改进。与这些方法不同，ReAct 做的不只是孤立、固定的推理，而是把模型行动及其对应观察整合进连贯的输入流，使模型推理更准确，并处理推理之外的任务（例如交互式决策）。

用于决策的语言模型

LLM 的强能力使其能执行语言生成之外的任务，把 LLM 当作交互环境中的策略模型正变得更流行。WebGPT（Nakano et al., 2021）用 LM 与网页浏览器交互、浏览页面，并从 ELI5（Fan et al., 2019）的复杂问题中推断答案。与 ReAct 相比，WebGPT 并不显式建模思考与推理过程，而是依赖昂贵的人类反馈做强化学习。在对话建模中，BlenderBot（Shuster et al., 2022b）与 Sparrow（Glaese et al., 2022）等聊天机器人，以及 SimpleTOD（Hosseini-Asl et al., 2020）等任务型对话系统，也训练 LM 决定 API 调用。与 ReAct 不同，它们同样不显式考虑推理过程，并依赖昂贵数据集与人类反馈收集来学习策略。相比之下，ReAct 学习策略的方式便宜得多，因为决策过程只需要用语言描述推理过程。6

LLM 也越来越多地被用于交互与具身环境中的规划与决策。在这方面或许与 ReAct 最相关的是 SayCan（Ahn et al., 2022）与 Inner Monologue（Huang et al., 2022b），它们用 LLM 做机器人行动规划与决策。在 SayCan 中，LLM 被提示直接预测机器人可采取的可能行动，再由基于视觉环境落地的可供性模型重排序以得到最终预测。Inner Monologue 通过加入所谓「内心独白」进一步改进，其实现为注入的环境反馈。据我们所知，Inner Monologue 是首个演示此类闭环系统的工作，ReAct 建立在其之上。然而我们主张 Inner Monologue 并不真正包含内心思考——第 4 节已详述。我们也注意到，在交互决策过程中把语言当作语义丰富的输入，在其他设定下也被证明成功（Abramson et al., 2020; Karamcheti et al., 2021; Huang et al., 2022a; Li et al., 2022）。越来越明显的是，在 LLM 的帮助下，作为基本认知机制的语言将在交互与决策中扮演关键角色。此外，LLM 的进展也启发了 Reed et al.（2022）这类多面、通才智能体的发展。

结论

我们提出了 ReAct——一种简单而有效的方法，用于在大语言模型中协同推理与行动。通过在多跳问答、事实核查与交互式决策任务上的多样实验，我们表明 ReAct 带来更优性能，并具有可解释的决策轨迹。尽管方法简单，具有大行动空间的复杂任务需要更多示范才能学好，而这很容易超出上下文学习的输入长度限制。我们在 HotpotQA 上探索了微调路径

读后评论 · 非论文原文

协议循环有了，运行时组合还没有

以下是读者评论，用来对照正文，不是作者摘要。开读前只需看导读里的浓缩段；此处供读完 §2–§4、表 2 与图 5 之后展开。

它规定的是一步轨迹，不是可组合的运行时

ReAct 把思考写成与 search / go to 并列的行动：思考不改环境，只改上下文。这对后来的 agent harness 几乎是默认协议——工具调用夹在自然语言旁白和观察之间。HotpotQA 上幻觉从 CoT 的 56% 掉到近 0%，ALFWorld 上稀疏思考把成功率从 45% 拉到 71%，说明「旁白」不是装饰。

Cordiverse 要的是另一层保证：卸掉组件时把副作用收回，依赖能声明、能随拓扑变化协调。ReAct 的生命周期停在「这条轨迹走完」。Wikipedia API 与 WebShop 按钮是焊死的行动空间；没有卸载语义，也没有「一次坏的思考如何隔离爆炸半径」。思考 / 行动 / 观察因此是动态组合的半截：循环发生了，回收与协调还没有。

和 Cordiverse 的接口

运行框架文献把工具套件、会话状态、子智能体编排写成 harness 的职责。这些职责在实现里，多半仍展开为 ReAct 循环。Cordiverse 把「模型合成可复用工具」标成组件级自修改的较窄前驱；ReAct 更窄——它调用已有 API，并不造工具，也不声明工具之间的依赖。它提供的是可检查的决策轨迹，以及图 5 那种改两句思考就能纠偏的可控性。缺的是：这些轨迹进入长跑 harness 之后，如何热替换工具、如何在交错组件之间保持可逆效应。

作者已点名、但仍开放

  • 上下文长度（结论）：大行动空间需要更多示范，少样本提示会顶满窗口。微调有苗头，但高质量人类轨迹仍缺。
  • 解码死循环（表 2）：重复同一思考 / 行动被归进推理错误；作者怀疑贪心解码，束搜索只是展望。
  • 工具质量：23% 失败来自空检索。落地依赖外部观察，观察差就难以恢复。
  • 伦理：实验故意不能真下单、不能改百科。把同一循环接到开放网络或物理环境，风险声明停在「研究者应意识到」。

一句话判断

价值在于把思考 / 行动 / 观察写成可提示、可微调、可被人编辑的协议，并在知识题与长程环境上证明只想或只做都不够。对未来智能体仍缺的是：行动空间不再焊死之后，如何安全更换工具、如何卸载与回收、如何表达依赖。ReAct 规定了循环怎么走；Cordiverse 要问的是，许多条循环叠在一起时如何组合。
