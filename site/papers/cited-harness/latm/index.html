全文导读

这篇论文不长，但容易把「会用工具」和「会造工具」读成同一件事。下面先给出主张、机制、证据与精读路径。读完这一页，再带着一个具体问题进入正文。

一句话主张。 让强模型当工具制造者，把一类任务写成可复用的 Python 函数；让轻量模型当工具使用者，只负责把新问题译成函数调用。造一次、用多次，再加调度器做功能缓存，就可以在接近全程 GPT-4 的成绩下，把平均服务成本摊薄。

和 AI 工程、智能体的关系

LATM 是 Cordiverse 引用的 [14]：模型合成可复用工具，被看作组件级自修改的较窄前驱。它解决的是「工具从哪来」——不再只调用计算器、搜索、现成 API，而是让模型为自己写出 Python 函数，并在后续同类请求上复用。

和「用工具」的工作（ReAct、Toolformer、Chameleon）相比，这里的关键切口是造与用拆开：贵模型付一次性的工具制造成本，便宜模型付反复出现的工具使用成本。缓存的也不是某句自然语言回答（如 GPTCache），而是一类请求的功能。它对 AI 工程的直接用处可以收成一句：把重复推理从「每次让大模型从头想」改成「大模型写函数，小模型填参再执行」。

它没有处理工具在运行时如何卸载、依赖如何声明——那是 Cordiverse 要补的时空可组合性。展开判断与开放问题见独立的读后评论，此处不占导读。

问题从哪来

外部工具能增强 LLM，但前提是已经有合适的工具。人类演化的转折点之一是会为自己制造工具；作者把这一想法迁到 LLM：遇到新任务时，不要只会调用别人写好的 API，而要能写出可复用的求解器。

服务侧还有第二层压力：请求以流到来，全程用 GPT-4 太贵，全程用 GPT-3.5 又做不对复杂算术与约束推理。缺的不是又一次思维链提示，而是一次可摊销的工具制造，以及一张能识别「这题属于已有函数，还是新任务」的调度表。

机制（工具制造者 / 使用者 / 调度器）

流水线分两阶段，工具制造内部再拆三步（图 2，第 4–5 页）：

  • 工具提出：按「示例编程」从 3 条示范写 Python 函数；跑不通就把报错追加进历史再试。
  • 工具验证：用 3 条验证样本生成单元测试。这一步主要示范「如何把自然语言译成函数调用」，并且只改测试里的调用、不改函数本体；同时给自动化放行提供可靠性检查。
  • 工具封装：把函数代码与译题示范打成手册，交给工具使用者。超过重试阈值则本轮制造失败。

工具使用者（如 GPT-3.5 Turbo）以上下文学习方式生成函数调用并执行，必要时再把返回值映射成选项。对每一类任务，制造只做一次。

调度器是第三个、也很便宜的 LLM：维护已有工具的 API 仓库。来了新实例，先在功能缓存里找兼容工具，找到就交给使用者；找不到就视为新任务，攒够同类实例再请制造者写新函数。调度本身用提示词即可，准确率在文中约 95%–96%（第 8 页）。

作者实际贡献了什么

  • 闭环框架 LATM：工具制造 / 工具使用拆分，工具实现为 Python 函数，而不是另训一个调用器。
  • 提出–验证–封装三步，使造工具过程可以少人或无人盯着跑通（提示词见附录 C）。
  • 功能缓存 + 调度器：缓存一类请求的功能，而不是缓存自然语言回答；覆盖流式、多任务到达。
  • 成本论证：GPT-4 造、GPT-3.5 用，六任务上常匹配或超过 GPT-4 + 思维链，成本从 O(nC) 降到 O(nc + C)（表 2）。

Our approach consists of two phases: 1) tool making: an LLM acts as the tool maker that crafts tools for a set of tasks, where a tool is implemented as a Python utility function. 2) tool using: another LLM acts as the tool user, which applies the tool built by the tool maker for problem-solving. This framework enables subsequent requests to access cached tools via their corresponding APIs, enhancing the efficiency of task resolution. Beyond enabling LLMs to create their own tools, our framework also uncovers intriguing opportunities to optimize the serving cost of LLMs: Recognizing that tool-making requires more sophisticated capabilities, we assign this task to a powerful, albeit resource-intensive, model. 摘要

近期研究指出，大语言模型（LLM）借助合适的外部工具，可提升其问题解决能力。本文进一步推进这一思路，提出一种闭环框架，称为 LLMs As Tool Makers（LATM），使 LLM 能够为自己的问题解决过程制造可复用的工具。我们的方法包含两个阶段：1）工具制造：由一个 LLM 充当工具制造者，为一组任务打造工具，工具实现为 Python 工具函数。2）工具使用：由另一个 LLM 充当工具使用者，应用工具制造者所构建的工具来解决问题。工具使用者可以与工具制造者是同一模型，也可以是不同模型。在问题解决服务端，工具制造使系统能够随着新请求的出现持续生成并缓存工具。该框架使后续请求可通过相应 API 访问已缓存的工具，从而提高任务求解效率。除了让 LLM 制造自己的工具之外，该框架还揭示了优化 LLM 服务成本的有趣机会：认识到工具制造需要更强的能力，我们将这一任务交给强大但资源消耗较大的模型；相反，较为简单的工具使用阶段则委托给轻量模型。这种策略性的分工使一次性的工具制造成本可以分摊到多次工具使用上，从而在保持较强性能的同时显著降低平均成本。此外，我们的方法通过缓存与复用工具提供了一种功能缓存：它存储的是一类请求的功能，而非 LLM 的自然语言回答，从而扩展了传统缓存机制的适用范围。我们在包括 Big-Bench 任务在内的多种复杂推理任务上评估了该方法。以 GPT-4 作为工具制造者、GPT-3.5 作为工具使用者，LATM 取得了与两个角色均使用 GPT-4 相当的性能，但推理成本显著更低。代码库见 https://github.com/ctlllll/LLM-ToolMaker。

The two-stage design allows LATM to allocate jobs in each stage to the most suitable LLM. Specifically, the tool-making process, which requires a high degree of capability, can be assigned to a powerful albeit resource-intensive model (e.g., GPT-4). On the other hand, the tool-using process, which is comparatively simpler, can be assigned to a lightweight and cost-effective model (e.g., GPT-3.5 Turbo). This approach not only enhances the problem-solving capabilities of LLMs, but also significantly reduces the average computational cost of addressing a series of tasks. As the tool-making process needs to be executed only once for a given functionality, the resulting tools can be reused across different task instances. This approach paves the way for a scalable and cost-efficient solution for handling complex task. For instance, consider a task where a user ask the LLM to schedule a meeting that works for everyone (e.g., in email conversations). Lightweight models like GPT-3.5 Turbo often struggle with such tasks that involve complex arithmetic reasoning. In contrast, more powerful models (e.g., GPT-4) can find the correct solutions, despite that the inference costs become much higher. LATM overcomes these hurdles by employing a powerful yet expensive model as the tool maker, and passing it to a cost-effective model as the tool user, for subsequent usage. After the tool has been forged, the lightweight tool user can use it to solve the task efficiently with high performance. This paradigm can similarly be applied to recurring tasks in various workflows, such as parsing and analyzing web documents into specific data formats or formulating routing plans that satisfy several custom requirements, or being used to solve popular games like the 24-game, Sudoku. In the context of serving cost reduction, LATM introduces the opportunity of creating a functional cache for the LLM server. Specifically, consider a streaming setting where the LLM server continuously receives a sequence of requests. Traditional cache systems, such as GPTCache (Zilliz, 2023), store the responses generated by the LLMs and reuse them for textually similar requests. However, with the capacity for tool-making that LATM introduces, the system can store tools crafted by the tool maker and reuse them for functionally analogous requests. This novel approach, combined with the strategic division of labor between the tool maker and tool user, has the potential to considerably reduce the average cost of serving a sequence of requests while maintaining high performance.

由于对给定功能只需执行一次工具制造，所得工具可以在不同任务实例之间复用。这为处理复杂任务铺就了一条可扩展且成本高效的路径。例如，考虑用户请 LLM 安排一次所有人都方便的会议（如在电子邮件对话中）。GPT-3.5 Turbo 这类轻量模型往往难以应对涉及复杂算术推理的任务；更强大的模型（例如 GPT-4）能找到正确解，但推理成本高得多。LATM 克服这些障碍的方式是：用强大但昂贵的模型当工具制造者，再把工具交给成本更低的模型当工具使用者，供后续使用。工具锻造完成后，轻量工具使用者就能高效、高质量地求解该任务。这一范式同样适用于各类工作流中的重复任务，例如把网页文档解析并分析成特定数据格式、制定满足若干自定义约束的路由计划，或用于求解 24 点、数独等流行游戏。

在降低服务成本的语境下，LATM 为 LLM 服务器创造了构建功能缓存的机会。具体而言，考虑流式场景：LLM 服务器持续接收一串请求。传统缓存系统（如 GPTCache (Zilliz, 2023)）存储 LLM 生成的回答，并在文本相似的请求上复用。然而，有了 LATM 引入的工具制造能力，系统可以存储工具制造者打造的工具，并在功能类似的请求上复用。这种新做法与工具制造者 / 工具使用者之间的策略性分工相结合，有望在保持高性能的同时，显著降低服务一串请求的平均成本。

Recent works have explored the potential of using external tools to supplement LLMs’ capabilities for complex tasks. Yao et al. (2023); Yang et al. In contrast, we use Python executors to create reusable tools for addressing other task instances. Furthermore, the separation of the tool maker and tool user enables the use of a lightweight model for most inferences, thus enhancing efficiency and cost-effectiveness in LATM. Adaptive generation in language models. In addition, recent research has proposed methods to adaptively control decoding in LLMs to improve text generation efficiency (Leviathan et al., 2022; Chen et al., 2023a; Xia et al., 2023). Speculative decoding is based on the notion that generating text tokens (a more expensive process) can be expedited with a faster yet less powerful model while approximating the performance of larger, costlier models by using them to score generated tokens (a much faster process). Our approach of passing tools from a more expensive model to a smaller, faster model also shares a similar spirit of adaptive computing. Instead of altering the decoding procedure, we transfer newly generated tools between models to boost both the performance and efficiency of an LLM in solving tasks. Language model cascades. There is recent evidence that LLMs can enable repeated interactions and that multiple LLMs can be combined to extend their capabilities further (Wu et al., 2022; Zhou et al., 2022; Dohan et al., 2022; Chen et al., 2023c). Our motivation aligns with these findings; however, rather than merely cascading LLMs, we identify task categories that can be better addressed using new tools generated by a larger model and assign each individual inference within that task category to a smaller model. LATM FOSTERS A FUNCTIONAL CACHE MECHANISM FOR LLM SERVING In real-world scenarios, tasks often arrive in a sequential stream. To address this, we introduce a third LLM, the dispatcher, that decides whether to engage the tool user or tool maker for each incoming task. While this tool selection function mirrors existing works (Lu et al., 2023; Shen et al., 2023; Schick et al., 2023; Paranjape et al., 2023), our dispatcher distinctively contributes to creating a functional cache—it discerns new tasks that cannot be resolved with existing tools, thereby triggering the tool maker to generate appropriate tools for these tasks. The dispatcher maintains a repository of existing tools crafted by the tool maker in the format of function APIs. Upon receipt of a new task instance, the dispatcher first attempts to locate a compatible tool within the cache. If such a tool is present, the dispatcher assigns the instance and corresponding tool to the tool user for resolution. However, if no suitable tool is available, the dispatcher identifies this as a novel task, either solving it with a powerful model or, if necessary, invoking a human labeler. These new instances are then cached until a sufficient number are amassed to craft a new tool, further enriching the functional cache. This mechanism allows for the functionally similar tasks to reuse these tools, expanding the coverage of the classic cache mechanism and reducing the overall serving cost. Given the simplicity of the dispatching task, a lightweight model equipped with appropriate prompts (See Appendix C) can efficiently serve as the dispatcher, adding only a marginal cost to the entire pipeline.

LATM 为 LLM 服务培育功能缓存机制

在现实场景中，任务往往以顺序流到达。为此，我们引入第三个 LLM——调度器，由它决定对每个到来的任务启用工具使用者还是工具制造者。这一工具选择功能与已有工作相呼应（Lu et al., 2023; Shen et al., 2023; Schick et al., 2023; Paranjape et al., 2023），但我们的调度器有一个独特贡献：它创建功能缓存——辨别无法用现有工具解决的新任务，从而触发工具制造者为这些任务生成合适的工具。

调度器以函数 API 的形式维护工具制造者打造的现有工具仓库。收到新任务实例后，调度器首先尝试在缓存中定位兼容的工具。若存在这样的工具，调度器就把该实例与相应工具交给工具使用者求解。然而，若没有合适工具，调度器将其识别为新任务，或用强大模型求解，或在必要时调用人工标注者。这些新实例随后被缓存，直到积累到足够数量以打造新工具，从而进一步丰富功能缓存。该机制使功能相似的任务能够复用这些工具，扩展了经典缓存机制的覆盖范围，并降低总体服务成本。鉴于调度任务本身简单，配备合适提示词（见附录 C）的轻量模型即可高效充当调度器，给整条流水线只增加边际成本。

CONCLUSION AND FUTURE WORK We introduced LATM, a closed-loop framework empowering large language models (LLMs) to create and utilize their own tools for diverse tasks. Our approach, inspired by human’s evolutionary strides in tool creation, employs two key stages: Tool Making and Tool Using. This division of labor allows us to harness the capabilities of advanced LLMs while significantly reducing computational costs. Our experiments confirmed the efficacy of LATM across various complex tasks, demonstrating that our framework performs comparably to resource-intensive models while being more cost-effective. In addition, we show that adding another dispatcher LLM can further provide flexibility to our framework, enabling on-the-fly tool creation and usage. In our evaluation process, we identified a significant lack of high-quality datasets that authentically represent daily human-computer interactions, including recurring tasks such as scheduling meetings or booking flights over email or phone calls, in their raw natural language format. We anticipate that our work will stimulate the research community to create such datasets, which could prove instrumental in cultivating the next generation of AI systems. These systems, capable of generating and applying their own tools, will be equipped to tackle complex tasks more effectively. An exciting avenue for future research is enabling the tool maker to refine and upgrade existing tools to manage new problem instances, much like in software development. This adaptability could further catalyze the evolution of the AI ecosystem, unlocking a wealth of opportunities.

结论与未来工作

我们提出了 LATM，一种闭环框架，使大语言模型（LLM）能够为自己的多样任务创建并使用工具。我们的方法受人类在工具创造上的演化步伐启发，采用两个关键阶段：工具制造与工具使用。这种分工使我们能够发挥先进 LLM 的能力，同时显著降低计算成本。我们的实验在多种复杂任务上证实了 LATM 的有效性，表明我们的框架在更具成本效益的同时，性能可与资源密集型模型相比。此外，我们表明再增加一个调度器 LLM，可以进一步为框架提供灵活性，使工具能够即时创建与使用。

在评估过程中，我们发现严重缺乏高质量数据集，能够以原始自然语言形式真实刻画日常人机交互，包括通过电子邮件或电话反复出现的排会、订机票等任务。我们期望本文能促使研究社区创建此类数据集，它们可能对培育下一代 AI 系统具有关键作用。这些系统能够生成并应用自己的工具，将更有效地应对复杂任务。一个令人兴奋的未来研究方向是：使工具制造者能够精炼并升级现有工具以处理新的问题实例，就像软件开发中那样。这种适应性可能进一步催化 AI 生态系统的演化，解锁大量机会。

读后评论 · 非论文原文

对 harness 有用，对运行时组合还不够

以下是读者评论，用来对照正文，不是作者摘要。开读前只需看导读里的浓缩段；此处供读完方法、表 2 与附录 B 之后展开。

它在工具谱系里站哪一层

LATM 不是又一个「调用现成 API」的智能体框架。它把工具写成 Python 函数：强模型从几条示范里提出、验证、封装，轻量模型只做译题与填参。和 ReAct / Toolformer 相比，重点从「何时调用已知工具」挪到「如何为新任务类造出可复用工具」。和思维链相比，函数是可执行、可缓存、可在实例间共享的求解器，而不是一段一次性的自然语言草稿。

对正在长出来的 agent harness，这很实用：重复出现的约束推理、解析、排期，不必每次都烧一遍最贵的模型。功能缓存比「缓存同一句话」更接近真实流量——同一类请求措辞可以变，算法结构仍在。

和 Cordiverse 的接口，也是缺口

Cordiverse 把 LATM 标成引用 [14]：模型合成可复用工具，是组件级自修改的较窄前驱。前驱在于——工具开始由模型生产，而不只是人注册。窄在于——LATM 的生命周期几乎停在「造出来、放进仓库、下次还能调」。

它不讨论工具在运行时如何卸载、替换时副作用如何收回，也不讨论工具之间的依赖如何声明、拓扑一变谁该停谁该等。功能缓存是一张越积越厚的 API 清单；调度器会为新任务再造函数，但没有「这条函数过期了、与另一条冲突了、权限该一并撤掉」的语义。那正是 Cordiverse 用可逆效应与反应式余效应要管的事：造得出，还要卸得干净、依赖跟得上。

作者已点名、但仍开放

  • 工具质量与安全（附录 B）：自主造工具是双刃剑。函数可能次优、错误、甚至有害；文中没有防护、审计或人可冻结的闸门。现实世界里如何验收这些工具，作者承认尚未处理。
  • 升级已有工具（结论）：现在是「新任务 → 新函数」。像软件开发那样精炼、版本化、在旧工具上打补丁，只是展望，调度器也不会做热替换。
  • 真实数据（结论）：六个评测里五个来自 Big-Bench，排会是模板合成。缺的是邮箱、电话里那种原始、重复、脏的人机交互语料。高分建立在干净、同类、可穷举的任务上。

读 harness 时额外要盯的

  • 验证阶段默认不改函数本体，只改单元测试里的调用。自动化友好，但一旦提出的算法系统性错了，验证过关也不等于工具对。
  • 难任务上必须用强模型当制造者（表 3）。把「模型会自己改脚手架」理解成全程便宜模型即可，会被这篇直接打脸。
  • 上下文里带着全部制造历史，长度与费用会涨；工具仓库变大之后，调度提示词里的 API 说明书本身会成为新的上下文税。

一句话判断

价值在于把「模型造 Python 工具 + 贵便宜分工 + 功能缓存」做成可复现的闭环，证明轻量模型可以站在强模型写出的函数上接近强模型的成绩。对未来智能体仍缺的是：这些函数进入长跑 harness 之后，如何安全升级、如何卸载与回收、如何表达依赖，以及如何在真实、肮脏的请求流里证明工具仍然可信。LATM 把工具生产出来了；Cordiverse 要问的是，生产之后如何组合。
