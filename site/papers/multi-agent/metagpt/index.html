全文导读

这篇容易被收成「又一个多智能体聊天框架」。下面先给出主张、机制、证据与精读路径。读完这一页，再带着一个具体问题进入正文。

一句话主张。 把人类软件公司的标准作业程序（SOP）编进提示：角色交结构化文档（PRD、设计、任务单），经共享消息池订阅，再加运行时可执行反馈。闲聊会传话走样；SOP 让多智能体写出更连贯、更能跑的软件。

和 AI 工程、智能体、Cordiverse 的关系

MetaGPT 是 harness 文献里「编排子智能体与多智能体工作流」的一张具体图纸：五角色流水线、发布–订阅、工程师自己跑单测。Cordiverse 把多智能体编排视为运行框架的职责之一；MetaGPT 证明结构化交接比 CAMEL / ChatDev 式对话更能压住级联幻觉。

它没有处理角色或工具在运行时如何卸载、一次坏的自修改如何隔离。消息池只会越积越厚。展开判断见读后评论。

问题从哪来

LLM 多智能体已经会简单对话，一接到复杂软件就逻辑崩：幻觉级联、「吃了吗」式闲聊、助手重复指令、消息死循环。人类靠 SOP 规定谁交什么中间产物。缺的不是更多角色扮演，而是把 SOP 写成可执行的元编程——「为编程而编程」。

机制（SOP + 消息池 + 可执行反馈）

  • 五角色：Product Manager → Architect → Project Manager → Engineer → QA Engineer；画像含目标与约束；行为遵循 ReAct 风格。
  • 结构化通信：交文档与图，不交无约束自然语言；订阅只取依赖，避免信息过载。
  • 可执行反馈：工程师对照 PRD / 设计跑单元测试，最多重试 3 次——不是只自我反思。

作者实际贡献了什么

  • 框架 MetaGPT：角色定义、消息共享、SOP 工作流，开源平台。
  • 数字：HumanEval 85.9%、MBPP 87.7% Pass@1；SoftwareDev 可执行性 3.75，人工修订 0.83。
  • 消融：去掉角色则代码不可用；去掉反馈则 Pass@1 掉 4.2% / 5.4%，修订升回 2.25。
  • 展望：跨项目自改进与 AgentStore 是附录，不是主实验。

摘要

基于大语言模型（LLM）的智能体社会在自动解题上已有显著进展。现有 LLM 多智能体系统已能解决简单对话任务。然而更复杂任务的解法常因朴素串联 LLM 造成级联幻觉，出现逻辑不一致。本文提出 MetaGPT，一种创新的元编程框架，把高效的人类工作流纳入基于 LLM 的多智能体协作。

MetaGPT 将标准作业程序（SOP）编码进提示序列，使工作流更顺畅，从而让具备类人领域专长的智能体能够核验中间结果并减少错误。MetaGPT 采用流水线范式，为不同智能体分配多样角色，把复杂任务高效拆成多个智能体共同完成的子任务。在协作软件工程基准上，MetaGPT 生成的解法比先前基于聊天的多智能体系统更连贯。项目见 https://github.com/geekan/MetaGPT。

RELATED WORK Automatic Programming The roots of automatic programming reach back deep into the previous century. In 1969, Waldinger & Lee (1969) introduced “PROW,” a system designed to accept program specifications written in predicate calculus, generate algorithms, and create LISP implementations (McCarthy, 1978). Balzer (1985) and Soloway (1986) made efforts to advance automatic programming and identified potential methods to achieve it. Recent approaches use natural language processing (NLP) techniques (Ni et al., 2023; Skreta et al., 2023; Feng et al., 2020; Li et al., 2022; Chen et al., 2018; 2021b; Zhang et al., 2023a; Liu et al., 2023b; Tang et al., 2023a; Muennighoff et al., 2023). Automatic programming has grown into an industry delivering paid functions such as Microsoft Copilot. Lately, LLMs-based agents (Yao et al., 2022; Shinn et al., 2023; Lin et al., 2023) have advanced automatic programming development. Among them, ReAct (Yao et al., 2022) and Reflexion (Shinn et al., 2023) utilize a chain of thought prompts (Wei et al., 2022) to generate reasoning trajectories and action plans with LLMs. Both works demonstrate the effectiveness of the ReAct style loop of reasoning as a design paradigm for empowering automatic programming. Additionally, ToolFormer (Schick et al., 2023) and ToolLLM (Qin et al., 2023) can learn how to use external tools through simple APIs. The research most closely aligned with our work by Li et al. (2023) proposes a straightforward role-play framework for programming that involves communication between agents playing different roles. Qian et al. (2023) utilizes multiple agents for software development. Although existing papers (Li et al., 2023; Qian et al., 2023) have improved productivity, they have not fully tapped into effective workflows with structured output formats. This makes it harder to deal with complex software engineering issues. LLM-Based Multi-Agent Frameworks Recently, LLM-based autonomous agents have gained tremendous interest in both industry and academia (Wang et al., 2023b; Zhou et al., 2023b; Zhang et al., 2023b). Many works (Chen et al., 2024; Wang et al., 2023c; Du et al., 2023; Zhuge et al., 2023; Hao et al., 2023; Akata et al., 2023; Tang et al., 2023b) have improved the problem-solving abilities of LLMs by integrating discussions among multiple agents. Stable-Alignment (Liu et al., 2023a) creates instruction datasets by deriving consensus on value judgments through interactions across a sandbox with LLM agents. Other works focus on sociological phenomena. For example, Generative Agents (Park et al., 2023) creates a “town” of 25 agents to study language interaction, social understanding, and collective memory. In the Natural Language-Based Society of Mind (NLSOM) (Zhuge et al., 2023), agents with different functions interact to solve complex tasks through multiple rounds of “mindstorms.” Cai et al. (2023) propose a model for cost reduction by combining large models as tool makers and small models as tool users. Some works emphasize cooperation and competition related to planning and strategy (Bakhtin et al., 2022); others propose LLM-based economies (Zhuge et al., 2023). These works focus on openworld human behavior simulation, while MetaGPT aims to introduce human practice into multiagents frameworks. Besides, LLM-based agents face the challenges of “assistant repeated instruction” or “infinite loop of message” (Talebirad & Nadiri, 2023; Li et al., 2023). These challenges become more urgent in task-oriented collaborations, which require consistent and mutually beneficial interactions (Elazar et al., 2021; Wang et al., 2022; Jiang et al., 2023). This motivates our focus on applying advanced concepts such as Standard Operating Procedures in software development to multi-agent frameworks.

自动编程的根可追溯到上世纪。1969 年，Waldinger & Lee（1969）提出 “PROW”，接受谓词演算写的程序规格、生成算法并产生 LISP 实现（McCarthy, 1978）。Balzer（1985）与 Soloway（1986）推进自动编程并指出可能路径。近期方法使用自然语言处理技术（Ni et al., 2023; Skreta et al., 2023; Feng et al., 2020; Li et al., 2022; Chen et al., 2018; 2021b; Zhang et al., 2023a; Liu et al., 2023b; Tang et al., 2023a; Muennighoff et al., 2023）。自动编程已成长为交付付费功能的产业，例如 Microsoft Copilot。近来，基于 LLM 的智能体（Yao et al., 2022; Shinn et al., 2023; Lin et al., 2023）推进了自动编程发展。其中 ReAct（Yao et al., 2022）与 Reflexion（Shinn et al., 2023）利用思维链提示（Wei et al., 2022）生成推理轨迹与行动计划。两文都证明 ReAct 风格的推理循环作为赋能自动编程的设计范式有效。此外，ToolFormer（Schick et al., 2023）与 ToolLLM（Qin et al., 2023）能通过简单 API 学会使用外部工具。与我们最接近的是 Li et al.（2023）提出的简单角色扮演编程框架，以及 Qian et al.（2023）用多个智能体做软件开发。尽管现有论文提升了生产力，它们尚未充分挖掘带结构化输出格式的有效工作流，因而更难处理复杂软件工程问题。

基于 LLM 的多智能体框架

近来，基于 LLM 的自主智能体在工业与学界都引起巨大兴趣（Wang et al., 2023b; Zhou et al., 2023b; Zhang et al., 2023b）。许多工作（Chen et al., 2024; Wang et al., 2023c; Du et al., 2023; Zhuge et al., 2023; Hao et al., 2023; Akata et al., 2023; Tang et al., 2023b）通过多智能体讨论提升 LLM 解题能力。Stable-Alignment（Liu et al., 2023a）通过沙盒中 LLM 智能体交互形成价值判断共识来构造指令数据。其他工作关注社会现象。例如 Generative Agents（Park et al., 2023）创建 25 个智能体的「小镇」以研究语言交互、社会理解与集体记忆。在基于自然语言的心智社会（NLSOM）（Zhuge et al., 2023）中，不同功能的智能体通过多轮「头脑风暴」交互以解决复杂任务。Cai et al.（2023）提出用大模型当工具制造者、小模型当工具使用者来降本。

CONCLUSION This work introduces MetaGPT, a novel meta-programming framework that leverages SOPs to enhance the problem-solving capabilities of multi-agent systems based on Large Language Models (LLMs). MetaGPT models a group of agents as a simulated software company, analogous to simulated towns (Park et al., 2023) and the Minecraft Sandbox in Voyager (Wang et al., 2023a). MetaGPT leverages role specialization, workflow management, and efficient sharing mechanisms such as message pools and subscriptions, rendering it a flexible and portable platform for autonomous agents and multi-agent frameworks. It uses an executable feedback mechanism to enhance code generation quality during runtime. In extensive experiments, MetaGPT achieves state-of-the-art performance on multiple benchmarks. The successful integration of human-like SOPs inspires future research on human-inspired techniques for artificial multi-agent systems. We also view our work as an early attempt to regulate LLM-based multi-agent frameworks. See also the outlook (Appendix A).

结论

本文提出 MetaGPT，一种新颖的元编程框架，利用 SOP 增强基于大语言模型（LLM）的多智能体系统的解题能力。MetaGPT 把一组智能体建模为模拟软件公司，类似于模拟小镇（Park et al., 2023）与 Voyager 中的 Minecraft 沙盒（Wang et al., 2023a）。MetaGPT 利用角色专门化、工作流管理以及消息池与订阅等高效共享机制，使其成为自主智能体与多智能体框架的灵活、可移植平台。它使用可执行反馈机制在运行时提升代码生成质量。在大量实验中，MetaGPT 在多个基准上达到最先进性能。成功融入类人 SOP 启发未来对人工多智能体系统采用人类启发技术的研究。我们也把本工作视为规范基于 LLM 的多智能体框架的早期尝试。另见展望（附录 A）。

Published as a conference paper at ICLR 2024 A OUTLOOK A.1 SELF-IMPROVEMENT MECHANISMS One limitation of the MetaGPT version in the main text of this paper is that each software project is executed independently. However, through active teamwork, a software development team should learn from the experience gained by developing each project, thus becoming more compatible and successful over time. This is somewhat related to the idea of recursive self-improvement, first informally proposed in 1965 (Good, 1965), with first concrete implementations since 1987 (Schmidhuber, 1987; 1993b; Schmidhuber et al., 1998), culminating in the concept of mathematically optimal self-referential self-improvers (Schmidhuber, 2003; 2009). Generally speaking, a system should learn from experience in the real world, and meta-learn better learning algorithms from experiences of learning, and meta-meta-learn better meta-learning algorithms from experiences of meta-learning, etc., without any limitations except those of computability and physics. More recent, somewhat related work leverages the reasoning ability of Large Language Models (LLMs) and recursively improves prompts of LLMs, to improve performance on certain downstream tasks (Fernando et al., 2023; Zelikman et al., 2023), analogous to the adaptive prompt engineer of 2015 (Schmidhuber, 2015) where one neural network learns to generate sequence of queries or prompts for another pre-trained neural network whose answers may help the first network to learn new tasks more quickly. In our present work, we also explore a self-referential mechanism that recursively modifies the constraint prompts of agents based on information they observe during software development. Our initial implementation works as follows. Prior to each project, every agent in the software company reviews previous feedback and makes necessary adjustments to their constraint prompts. This enables them to continuously learn from past project experiences and enhance the overall multi-agent system by improving each individual in the company. We first establish a handover feedback action for each agent. This action is responsible for critically summarizing the information received during the development of previous projects and integrating this information in an updated constraint prompt. The summarized information is stored in long-term memory such that it can be inherited by future constraint prompt updates. When initiating a new project, each agent starts with a react action. Each agent evaluates the received feedback and summarizes how they can improve in a constraint prompt. One current limitation is that these summary-based optimizations only modify constraints in the specialization of roles (Sec. 3.1) rather than structured communication interfaces in communication protocols (Sec. 3.2). SOP 管住了闲聊，还没有管住卸载

以下是读者评论，用来对照正文，不是作者摘要。开读前只需看导读里的浓缩段；此处供读完 §3、表 1 与附录 A 之后展开。

它解决的是「传话走样」，不是「可组合的运行时」

MetaGPT 的现场很清楚：五个角色按标准作业程序交 PRD、系统设计、任务单；消息池发布、按画像订阅；工程师对照文档跑单测，最多三轮。这比 CAMEL / ChatDev 的自由对话更能压住「吃了吗」式幻觉，表 1 的可执行性 3.75 与修订 0.83 不是装饰。

Cordiverse 要的是时间可组合性（卸掉时副作用收回）与空间可组合性（依赖可声明、拓扑一变能协调）。这篇几乎不谈卸载。消息池是越积越厚的全局黑板；角色是开跑前焊死的编制。一次坏的工程师自修改，没有隔离爆炸半径的语义。SOP 因此是多智能体编排的半截：交接发生了，回收还没有。

和 Cordiverse 的接口

运行框架要把「编排子智能体」写成职责。MetaGPT 提供一份可复现的编排：结构化中间产物 + 发布订阅 + 可执行反馈。它甚至让每个智能体走 ReAct 风格循环。Cordiverse 会问：这些角色和文档进入长跑服务之后，如何热替换一个岗位、如何让依赖方发现接口变了、如何在不重启整家「公司」的情况下撤掉一条坏技能。附录 A 的跨项目自改进与 AgentStore，把问题推向「越做越强」和「上架新智能体」，仍然不是卸载与依赖规约。

作者已点名、但仍开放

  • 项目彼此遗忘（附录 A）：每个软件项目独立执行，团队不从上一单学习。递归自改进只是展望。
  • 上下文与幻觉（附录 E）：短需求要展开，长上下文要防过期；代码幻觉（缺依赖、半截函数）SOP 只能缓解。
  • 分数绑底座（表 7）：HumanEval 对提示与解析敏感；85.9% 是框架加 GPT-4，不是任意小模型套上五顶帽子就行。
  • 需求漂移（附录 B）：用户说画图，PRD 写成取色器——结构化格式正确，理解仍可偏。

一句话判断

价值在于把标准作业程序写成可运行的元编程：结构化交接 + 订阅 + 跑得通的反馈，并在函数题与小型工程上压过聊天式多智能体。缺口是：编制焊死、消息池只增不减、跨项目学习与卸载未做。Cordiverse 要补的，正是这家模拟公司还没写进员工手册的那一页：岗位如何卸得干净。
